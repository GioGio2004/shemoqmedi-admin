The storefront is the public site at `www.shemoqmedi.space`, in the `shemoqmedi` repo. It is a Next.js 16 app (React 19, Tailwind 4) on Vercel. It has no database of its own: public pages read the shared Convex backend on the server and are served as cached static HTML, while a small group of signed-in pages talk to Convex live through Clerk.

## Route groups

The `app/` folder has two route groups and a few special files.

- `app/(site)/` holds the public pages. Its layout adds the footer and analytics. No Clerk or Convex client runs here.
- `app/(auth)/` holds pages that need a session. Its layout mounts `ClerkProvider` and `ConvexClientProvider`. No analytics run here.
- `app/layout.tsx` is the root layout for everything: font, default metadata, icons, the shared `Header`, and the Cloudflare Web Analytics beacon.

## How data is read

### Server reads: `lib/listings.ts`

Every public page gets its data from functions in `lib/listings.ts`, such as `getPublicListings`, `getListing`, `getPublicSlugs`, `getCreator`, `getJurors`, `getAward` and `getAwardSlugs`. They call Convex with `fetchQuery` from `convex/nextjs`.

Rules to know:

- `fetchQuery` is an HTTP POST, which Next will not cache. That is why every page that uses these functions exports `dynamic = "force-static"` and a `revalidate` time. Forget it and the page becomes dynamic on every request.
- Reads are wrapped in React `cache()` so `generateMetadata` and the page share one request.
- Errors: during `next build`, a failed read falls back to an empty result so a Convex outage cannot fail a deploy. At runtime it throws, so Next keeps serving the last good page instead of caching an empty one.
- A real "not found" is a `null` result, not an error.
- `getPublicListings` returns every public listing (up to 200). Pages filter in code.
- Renamed listings: `lib/slugRedirect.ts` asks Convex for the current slug and the page answers with a permanent redirect.

### The hand-typed Convex API: `convex-helpers-api.ts`

The Convex backend lives in the admin repo, so the storefront has no generated `api` object. `convex-helpers-api.ts` declares, by hand, the types of every Convex function the storefront calls (`listings`, `media`, `votes`, `creators`, `claims`, `users`, `jury`, `claimLinks`, `awards`, `rounds`, `conflicts`, `digest`) and exports `api` as a typed `anyApi`.

<Callout kind="warning">TypeScript cannot catch drift between this file and the real backend. When you change a Convex function used by the storefront, update `convex-helpers-api.ts` in the same change, and deploy the backend first if the storefront depends on a new field.</Callout>

### Client reads

Only the `(auth)` pages use the Convex React client (`components/ConvexClientProvider.tsx`) with the Clerk token. Uploads from `/submit` go through `lib/imagekitUpload.ts` (screenshots to ImageKit as WebP) and `lib/videoUpload.ts` (videos to Cloudflare R2).

### Images

`components/site/MediaImage.tsx` serves images through Vercel's image optimizer in front of ImageKit (WebP only, cached 31 days, see `images` in `next.config.ts`). Setting `NEXT_PUBLIC_IMAGE_CDN=imagekit` switches to ImageKit's own resizing (`lib/imageLoader.ts`).

## Shared header and the crow

There is one `Header` (`components/site/Header.tsx`), rendered in the root `app/layout.tsx` above every route group, so the navbar stays put on every page, including sign-in and account.

- The header is fixed and transparent, and turns into white glass on scroll.
- `components/site/MegaMenu.tsx` is the full-screen menu: pages, categories, technologies, a few covers and live search. Opens from the Menu button, the search field, `/` or Ctrl or Cmd plus K. Its links are server-rendered; its data loads from `/api/menu` on first use.
- `components/site/NavCrow.tsx` is the crow's home slot in the logo. The animated crow flies in, lands there and then roams the page. Logic is in `components/site/crow/` (`roam.ts`, `sprites.ts`, `world.ts`); sprite sheets are in `public/crow/`. Add `?crowdebug` to a URL for debug mode.

## SEO files

- `lib/site.ts`: the canonical origin (`SITE_URL`), `absoluteUrl()`, and the official social profiles used as `sameAs`.
- `app/sitemap.ts` and `app/robots.ts`: see the SEO page.
- JSON-LD: each public page writes its own `application/ld+json` script (types include `WebSite`, `Organization`, `CollectionPage`, `ItemList`, `BreadcrumbList`, `ProfilePage`, `CreativeWork`, `VideoObject`).
- `lib/imageSeo.ts`: image and video data shared by listing pages and the sitemap.
- OG images: `app/opengraph-image.tsx` is the default; pages that set their own `openGraph` must repeat `siteName`, `locale`, `type` and `images`, because Next merges metadata one level deep.

## Old Voloo pages: 410 Gone

The domain used to host Voloo (NFC tap menus). Its old URLs are handled in two ways:

1. Old URLs that have a live equivalent are permanently redirected in `next.config.ts` (`redirects()`): the `/en`, `/ka/...` and `/ru` locale prefixes, `/category/...` to `/collections/...`, `/collections/sotd` to `/site-of-the-day`, and `/t/...` (old NFC stickers) to the home page.
2. Everything else from Voloo answers **410 Gone** from `proxy.ts`, using the path list and HTML in `lib/gone.ts`. The response carries `X-Robots-Tag: noindex`.

<Callout kind="warning">The 410 path list exists twice: in `lib/gone.ts` and as literals in the `matcher` of `proxy.ts` (Next needs literals there). Change both together. `/ka` itself is the live Georgian page and must never be marked gone.</Callout>

## Security headers

`next.config.ts` sets HSTS, `nosniff`, a referrer policy, a permissions policy and a `frame-ancestors` rule. Only the site itself and Giorgi's portfolio may show the site in a frame. Any host other than `www.shemoqmedi.space` (for example `*.vercel.app` aliases) gets `X-Robots-Tag: noindex`.
